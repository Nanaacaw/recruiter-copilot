# Database Migrations (Alembic)

Project ini menggunakan **Alembic** untuk mengelola perubahan schema database. Semua perubahan tabel — tambah kolom, ubah tipe data, hapus index — harus lewat migration file, bukan raw SQL manual.

---

## Struktur File

```
backend/
├── alembic.ini          # konfigurasi Alembic (script_location = migrations)
├── migrations/
│   ├── env.py           # setup engine & metadata
│   ├── script.py.mako   # template migration
│   └── versions/
│       └── 001_initial.py   # migration pertama
```

Folder dinamai `migrations/` (bukan `alembic/`) untuk menghindari name collision dengan package `alembic` dari PyPI.

---

## Setup (One-Time)

Sudah selesai saat ini. Yang sudah dibuat:

1. `alembic==1.13.1` di `requirements.txt`
2. Folder `migrations/` dengan `env.py`, `script.py.mako`, `versions/`
3. Initial migration `001_initial.py`
4. `Dockerfile` copy `migrations/` ke image
5. `main.py` auto-run `alembic upgrade head` saat startup

---

## Workflow Sehari-Hari

### 1. Tambah Kolom Baru

**Step 1: Edit model SQLAlchemy**

Contoh: tambah `notes` ke `Screening`

```python
# backend/app/models/models.py
class Screening(Base):
    __tablename__ = "screenings"
    # ... kolom existing ...
    notes = Column(Text, nullable=True)  # ← baru
```

**Step 2: Generate migration**

```powershell
cd backend
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_screening"
venv\Scripts\python.exe -m alembic revision --autogenerate -m "add notes to screenings"
```

> **Cmd.exe user:** pakai `set DATABASE_URL=...` (bukan `$env:...`)

**Step 3: Review file yang dihasilkan**

Buka `migrations/versions/002_....py`, pastikan `upgrade()` dan `downgrade()` benar:

```python
def upgrade() -> None:
    op.add_column('screenings', sa.Column('notes', sa.Text(), nullable=True))

def downgrade() -> None:
    op.drop_column('screenings', 'notes')
```

> **Wajib review.** Alembic kadang salah detect rename (jadi drop+add) atau miss constraint changes.

**Step 4: Apply migration**

```powershell
venv\Scripts\python.exe -m alembic upgrade head
```

## Command Reference

| Command | Fungsi |
|---------|--------|
| `alembic current` | Lihat versi migration yang aktif sekarang |
| `alembic history` | Lihat semua migration dari awal sampai sekarang |
| `alembic upgrade head` | Apply semua pending migration |
| `alembic downgrade -1` | Rollback 1 migration terakhir |
| `alembic downgrade 001` | Rollback sampai revision `001` |
| `alembic revision --autogenerate -m "msg"` | Generate migration dari perubahan model |
| `alembic revision -m "msg"` | Buat migration kosong (tulis manual) |

## Environment Variable

Alembic membaca `DATABASE_URL` dari environment. Di project ini, `migrations/env.py` import `settings.DATABASE_URL` yang membaca dari `.env`.

**Untuk local dev (PostgreSQL container):**

```powershell
# PowerShell
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5433/ai_screening"

# Cmd.exe
set DATABASE_URL=postgresql://postgres:postgres@localhost:5433/ai_screening
```

**Kenapa perlu override?**

File `.env` punya `DATABASE_URL` dengan hostname `db` (untuk Docker internal network). Dari Windows lokal, hostname `db` tidak ter-resolve — harus pakai `localhost:5433`.

## Troubleshooting

### `No module named alembic`

Package belum terinstall di venv. Install:

```powershell
venv\Scripts\python.exe -m pip install alembic==1.13.1
```

### `No config file 'alembic.ini' found`

Jalankan command dari folder `backend/` (bukan root project). File `alembic.ini` ada di `backend/alembic.ini`.

### `could not translate host name "db" to address`

`DATABASE_URL` di `.env` pakai hostname `db` untuk Docker. Saat run Alembic dari lokal, override ke `localhost:5433`:

```powershell
set DATABASE_URL=postgresql://postgres:postgres@localhost:5433/ai_screening
venv\Scripts\python.exe -m alembic upgrade head
```

### `No module named 'psycopg2'`

Install ke venv:

```powershell
venv\Scripts\python.exe -m pip install psycopg2-binary==2.9.9
```

## Best Practices

1. **Never edit migration yang sudah di-apply** — kalau salah, buat migration baru untuk fix.
2. **Always review autogenerated migration** — cek `upgrade()` dan `downgrade()` sebelum apply.
3. **Test downgrade** sebelum commit — pastikan rollback berfungsi.
4. **Nama migration deskriptif** — `add notes to screenings` lebih baik dari `update`.
5. **Satu migration per logical change** — jangan bundle banyak perubahan unrelated.
6. **Commit migration file bersama code change** — migration harus masuk Git bersama perubahan model.

## Docker / Production

Di container, migration otomatis jalan saat startup karena `main.py` panggil:

```python
alembic_cfg = Config("alembic.ini")
command.upgrade(alembic_cfg, "head")
```

**Catatan untuk skala besar:**

Auto-migration saat startup praktis untuk self-hosted, tapi untuk production dengan banyak instance, lebih aman jalankan `alembic upgrade head` manual sebelum deploy — supaya bisa monitor dan rollback kalau ada masalah.

## Membuat Migration Manual (Tanpa Autogenerate)

Kalau autogenerate tidak detect perubahan (misalnya complex constraint), buat migration kosong:

```powershell
venv\Scripts\python.exe -m alembic revision -m "add composite index"
```

Lalu edit file yang dihasilkan, tulis `upgrade()` dan `downgrade()` sendiri:

```python
def upgrade() -> None:
    op.create_index('ix_screening_score', 'screenings', ['overall_score'])

def downgrade() -> None:
    op.drop_index('ix_screening_score', table_name='screenings')
```

Referensi operation: https://alembic.sqlalchemy.org/en/latest/ops.html
